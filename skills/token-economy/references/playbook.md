# Playbook de economia (detalhes)

## Ordem de ataque (do maior ganho ao menor)
1. Parar de ler arquivos inteiros (buscar + trechos).
2. Filtrar saída de comandos.
3. `/clear` entre tarefas e `/compact` antes de encher.
4. Delegar barulho a subagentes baratos com resposta curta.
5. Enxugar CLAUDE.md, MCP e skills instaladas.
6. Escolher modelo e esforço pelo tamanho da tarefa.
7. Respostas diretas (sem preâmbulo e sem recap).

## Quando NÃO economizar
- Segurança, dados e produção: confira de verdade, mesmo que custe mais.
- Requisito ambíguo: uma pergunta curta ao usuário custa menos que construir a coisa errada.
- Primeira leitura de um código desconhecido que você vai alterar: leia o suficiente para não quebrar nada.

## Pedidos úteis ao usuário
- "Posso rodar só o teste afetado em vez da suíte completa?"
- "Quer que eu faça `/compact` agora? Estamos com contexto grande."
- "Esta tarefa é mecânica; posso usar o Haiku por subagente?"
